# ONNX Runtime shared libraries shipped next to `dreamcore` (loaded at run time,
# see crates/dream-domain-devops/src/onnxruntime.rs).
#
# Production must not depend on one code-hosting URL. The upstream
# microsoft/onnxruntime GitHub repository went away on 2026-11-20 (every release
# URL 404'd and two release builds failed), so GitHub release archives are NOT
# used any more. Each target lists its sources in order; the first one that
# downloads AND matches its sha256 is used (scripts/fetch-onnxruntime.*):
#
#   <rust-target> <url> <sha256>
#
#  1. Our own COS mirror (onework-1521070673/build-deps/onnxruntime/1.28.3/…): the
#     exact 1.28.3 libraries that dreamcore v0.1.105 and the 1.0.17 / 1.0.18
#     enterprise images were built and tested with, byte for byte. Raw files.
#  2. The official `onnxruntime` 1.28.0 wheel on PyPI (a zip carrying the same CPU
#     build under onnxruntime/capi/). 1.28.3 was only ever published on GitHub, so
#     PyPI's closest release of the same minor is the fallback. Same minor =
#     the C API the `ort` crate (2.0.0-rc.13, "ONNX Runtime 1.28") is built for.
#
# Mirror files are write-once: never replace an object under a version directory,
# add a new version directory and a new pin instead (the sha256 below is of the
# exact bytes).
#
# x86_64-apple-darwin is deliberately absent: no Intel Mac build is published,
# so local embedding is unavailable there (the program reports it; a remote
# embedding endpoint still works).
#
# Bumping: upload the new build to a new COS directory (build-deps/onnxruntime/<ver>/
# <target>/<file>), add its sha256 here, and refresh the PyPI fallback from
#   https://pypi.org/pypi/onnxruntime/<version>/json   (urls[].url / .digests.sha256)
# Stay on 1.28.x until the `ort` crate is bumped. Run scripts/fetch-onnxruntime.* once
# per platform afterwards, and the embedding acceptance test:
#   cargo test -p dream-domain-devops --test local_embedding_fresh_install -- --ignored
