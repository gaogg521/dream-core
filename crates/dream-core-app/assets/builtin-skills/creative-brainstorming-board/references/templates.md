## 5 栏白板结构模板

### 格式定义
用于绘制标准的 5 栏白板，确保从左到右的信息流结构一致。

### 白板布局

```md
| 现实世界<br>Reality / Use Case | 约束边界<br>Constraints | 本质拆解<br>First Principles | 方案假设<br>Hypotheses | 问题 & 推进<br>Risks / Next |
| :----------------------------: | :---------------------: | :--------------------------: | :--------------------: | :------------------------: |
```



### 第一栏：现实世界（Reality / Use Case）

**核心问题**：谁，在什么状态下，会遇到这个问题？

**关键词格式**：每条 3-5 个字

**填写规范**：
- ❌ 禁止出现"产品"二字
- ❌ 禁止抽象形容词（"智能"、"高效"）
- ✅ 只写具体场景和状态

**模板**：

```
第一栏：现实世界
─────────────────────────
• [关键词1]
• [关键词2]
• [关键词3]
• [关键词4]
• [关键词5]
• [关键词6]
• [关键词7]
• [关键词8]
• [关键词9]
• [关键词10]

总计：10-15 个关键词
```

**完整示例**：

```
第一栏：现实世界
─────────────────────────
• 单人车内进食
• 儿童餐具
• 奶瓶
• 外卖残渣
• 异味
• 没时间洗
• 不想带回家
• 扶手箱
• 后备箱
• 长途自驾
```

### 第二栏：约束边界（Constraints）

**核心问题**：什么东西是你绝对不能违反的？

**四个必须维度**：
1. 空间
2. 能源
3. 液体
4. 安全

**模板**：

```
第二栏：约束边界
─────────────────────────
空间：
• [关键词1]
• [关键词2]
• [关键词3]

能源：
• [关键词4]
• [关键词5]
• [关键词6]

液体：
• [关键词7]
• [关键词8]
• [关键词9]

安全：
• [关键词10]
• [关键词11]
• [关键词12]

总计：10-15 个关键词
```

**完整示例**：

```
第二栏：约束边界
─────────────────────────
空间：
• 后备箱
• 扶手箱
• 20-30L

能源：
• 12V
• 低功率
• 禁止高温

液体：
• 封闭水
• 防晃
• 无外排

安全：
• 行驶中
• 无蒸汽
• 无泄漏
```

### 第三栏：本质拆解（First Principles）

**核心问题**：我们到底在解决哪一个"功能本质"？

**写法规则**：
- 必须写成「动词 + 对象」格式
- 必须区分"必需"和"非必需"

**模板**：

```
第三栏：本质拆解
─────────────────────────
必需功能：
• [动词1] + [对象1]
• [动词2] + [对象2]
• [动词3] + [对象3]
• [动词4] + [对象4]
• [动词5] + [对象5]

─────────────────────────
非必需（可删除）：
• [功能6]
• [功能7]
• [功能8]
• [功能9]
```

**完整示例**：

```
第三栏：本质拆解
─────────────────────────
必需功能：
• 去除残渣
• 去除油脂
• 抑制细菌
• 防止腐败
• 存放餐具

─────────────────────────
非必需（可删除）：
• 高温
• 喷淋
• 干燥
• 完全无水渍
```

### 第四栏：方案假设（Heuristic Hypotheses）

**核心问题**：如果不用传统方法，还能怎么做？

**写法规则**：
- 每条必须以 **"不用 X，改用 Y"** 格式
- 基于第三栏的"非必需功能"进行创新
- 禁止品牌、技术名词堆砌、具体尺寸

**模板**：

```
第四栏：方案假设
─────────────────────────
• 不用 [X1]，改用 [Y1]
• 不用 [X2]，改用 [Y2]
• 不用 [X3]，改用 [Y3]
• 不用 [X4]，改用 [Y4]
• 不用 [X5]，改用 [Y5]
• 不用 [X6]，改用 [Y6]
• 不用 [X7]，改用 [Y7]
• 不用 [X8]，改用 [Y8]

总计：8-12 个假设
```

**完整示例**：

```
第四栏：方案假设
─────────────────────────
• 不用高温，改用化学 + 时间
• 不用喷水，改用旋转擦洗
• 不用排水，改用封闭循环
• 不用立刻洗，改用抑菌暂存
• 不用机械刷洗，改用超声波 + 酶
• 不用水，改用干冰
• 不用电力，改用太阳能
• 不用手动，改用自动感应
```

### 第五栏：问题 & 推进点（Risks / Next）

**核心问题**：哪里最可能被打脸？

**必须包含的内容**：
- 每个方案假设的最大风险点
- 用户的接受度问题
- 技术可行性疑问
- 成本和量产疑问

**模板**：

```
第五栏：问题 & 推进
─────────────────────────
方案假设风险：
• [假设1] 的风险：[风险描述]
• [假设2] 的风险：[风险描述]
• [假设3] 的风险：[风险描述]

用户接受度：
• [问题1]
• [问题2]
• [问题3]

技术可行性：
• [问题4]
• [问题5]

成本 & 量产：
• [问题6]
• [问题7]

总计：10-15 个风险点

─────────────────────────
关键推进点（选择 1-2 个）：
1. [推进点1] → 下一步：[具体行动]
2. [推进点2] → 下一步：[具体行动]
```

**完整示例**：

```
第五栏：问题 & 推进
─────────────────────────
方案假设风险：
• "不用高温，改用化学 + 时间" 的风险：化学残留安全性
• "不用排水，改用封闭循环" 的风险：细菌滋生
• "不用水，改用干冰" 的风险：用户接受度

用户接受度：
• 行驶中晃动是否影响清洁？
• 用户是否信任化学清洁？
• 清洁心理阈值如何？

技术可行性：
• 化学酶的抑菌效果是否足够？
• 旋转擦洗的清洁力是否达标？
• 封闭循环的维护成本？

成本 & 量产：
• 化学药剂的成本？
• 超声波模块的成本？
• 是否符合安全认证？

总计：12 个风险点

─────────────────────────
关键推进点（选择 1-2 个）：
1. 化学酶抑菌效果 → 下一步：实验室测试对比化学酶和高温的抑菌效果
2. 用户接受度 → 下一步：用户调研，了解用户对化学清洁的接受程度
```

## 白板迭代记录模板

### 格式定义
用于记录白板的版本演进，保留"为什么走到这里"的推理痕迹。

### 迭代记录结构

**版本信息**：
- 版本号：V1, V2, V3...
- 日期：[日期]
- 迭代触发：从上一版的哪个推进点触发

**迭代重点**：
- 上一版白板的关键风险点
- 新版本重点解决的问题
- 主要变化点

**完整示例**：

```
白板迭代记录
─────────────────────────

【V1 - 初始版本】
日期：2024-01-31
迭代触发：问题初始化

关键风险点：
• 化学酶抑菌效果未知
• 行驶中晃动影响清洁
• 用户对化学清洁接受度低

─────────────────────────

【V2 - 验证化学酶方案】
日期：2024-02-05
迭代触发：V1 推进点 1（化学酶抑菌效果）

关键变化：
• 第一栏：加入"化学酶安全"作为现实约束
• 第二栏：增加"无毒、可降解"的化学约束
• 第三栏：明确"抑制细菌"的安全标准
• 第四栏：提出"不用化学，改用紫外线"的备选假设

新风险点：
• 紫外线穿透力不足
• 紫外线灯的能源消耗
• 紫外线辐射安全

─────────────────────────

【V3 - 探索组合方案】
日期：2024-02-10
迭代触发：V2 推进点 2（紫外线穿透力不足）

关键变化：
• 第四栏：提出"不用单一方法，改用组合方案"
  - 不用纯化学，改用化学 + 低温
  - 不用纯紫外线，改用紫外线 + 旋转擦洗
• 第五栏：新风险点变为"方案复杂度"、"成本控制"

新风险点：
• 多方法组合的可靠性
• 系统复杂度增加
• 成本超支风险
```

## 验证计划模板

### 格式定义
用于规划对关键假设的验证方法，确保快速迭代。

### 验证计划结构

**假设命题**：
- 格式："如果我们采用 [不用 X，改用 Y]，那么应该观察到 [结果]"

**验证方法**：
- 最小化测试：用最简单的方式验证
- 定性验证：先定性，再定量

**成功标准**：
- 什么样的结果才算验证成功

**时间计划**：
- 预计完成时间

**完整示例**：

```
验证计划
─────────────────────────

【验证 1：化学酶抑菌效果】

假设命题：
如果我们采用"不用高温，改用化学酶 + 30分钟时间"，
那么应该达到与高温消毒（80℃，10分钟）相同的抑菌效果。

验证方法：
• 实验室测试：对比化学酶和高温对大肠杆菌、金黄色葡萄球菌的杀灭率
• 测试条件：化学酶方案（常温，30分钟） vs 高温方案（80℃，10分钟）
• 重复次数：每组测试重复 3 次

成功标准：
• 化学酶方案的抑菌率 ≥ 90%
• 与高温方案的差异 ≤ 5%

时间计划：
• 第 1-2 天：准备实验材料和菌株
• 第 3-4 天：执行测试
• 第 5 天：数据分析

─────────────────────────

【验证 2：用户接受度】

假设命题：
如果我们采用"不用水洗，改用化学清洁"，
那么用户对"餐具化学清洁"的接受度 ≥ 60%。

验证方法：
• 用户访谈：邀请 10-15 位目标用户
• 场景：车内用餐后，使用化学清洁方案处理餐具
• 测量：用户接受度（1-10分）、安全顾虑、购买意愿

成功标准：
• 接受度（≥6分）的用户比例 ≥ 60%
• 安全顾虑比例 ≤ 30%

时间计划：
• 第 1-3 天：招募用户
• 第 4-7 天：执行访谈
• 第 8 天：数据分析

─────────────────────────

【验证 3：行驶中晃动影响】

假设命题：
如果我们采用"封闭水 + 防晃设计"，
那么在行驶中（速度 60km/h，颠簸路面）不会发生水溢出。

验证方法：
• 模拟测试：在振动台上模拟行驶环境
• 测试条件：60km/h 速度等效振动，连续 30 分钟
• 观察指标：水溢出情况、容器完整性

成功标准：
• 无水溢出
• 容器无变形或破裂

时间计划：
• 第 1 天：设计测试装置
• 第 2 天：执行测试
• 第 3 天：分析结果
```

## 验证规则

### 白板模板验证
- 5 栏结构完整，每栏内容符合格式要求
- 关键词每条 3-5 字
- 第四栏假设严格遵循"不用 X，改用 Y"格式
- 禁止内容（UI、外观、BOM、智能/AI、市场规模）未出现

### 迭代记录验证
- 每个版本有明确的触发点
- 保留版本间的变化逻辑
- 风险点清晰可见

### 验证计划验证
- 假设命题格式正确
- 验证方法可执行
- 成功标准具体可衡量
