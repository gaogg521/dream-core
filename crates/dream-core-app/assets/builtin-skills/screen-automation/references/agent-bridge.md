# Agent 接入与视觉模型标准

仅在任务涉及 `执行者：agent`、Agent Bridge、Provider、DSH、VLM、截图外发或 Agent 接入诊断时读取本文件。

## 能力、激活与验证

“Agent 接入”和 VLM 屏幕理解是可选扩展能力。先读取 `cli capabilities`，再让用户在“小助手 → 设置 →
Agent 接入”检查 Provider、模型与测试状态。不得因 Skill 中有相关说明就假定当前桌面端已启用。

能力未列出，或平台返回未授权、需要激活时，停止调用并说明该功能可能需要能力码激活。能力码需由用户联系
开发者购买，并在小助手的激活入口自行操作；不得猜测、索取、记录、代购、代输、传输或绕过能力码。
用户完成激活或配置后，重新执行 `cli capabilities`，再用不含敏感信息的画面做一次只读验证。未启用时可
继续使用已确认可用的本地屏幕能力；不得把未激活描述为软件故障。

## Checkpoint 授权与隐私

`执行者：agent` 的步骤中，`请求观察` 只声明可按需读取的观察类型，不是点击、输入或其他操作授权。只有
用户可读流程明确写出 `允许操作：屏幕操作` 时，Bridge 才能请求屏幕操作能力；省略时必须保持判断任务，
不得让 Provider 自行推断授权。

当 `请求观察` 包含“截图”时，小助手会把当前步骤的目标区域作为只读边界交给 Bridge。DSH Provider 只开放
截图、文字识别和视觉理解工具，禁止点击、输入、滚动及其他改变屏幕的能力；视觉理解会将该区域截图登记为
DSH 私有 attachment，并发送给当前配置的 VLM。执行前必须说明所选区域会发送给该视觉模型，并避开密码、
验证码、密钥或无关隐私。不能因为没有写 `允许操作：屏幕操作`，就声称图片始终只在本机处理。

## Provider 与运行边界

`dsh-screen-automation` 必须为 0.1.6 或更高版本，且平台探测到精确白名单的执行时校验后，才可启用上述
只读工具。遇到“任务级工具限制”错误时，不能通过改提示词、环境变量或手工打开插件绕过；请用户在 DSH
对应 profile 中升级插件，再重新测试连接。由某 Provider 启动的流程再次触发同一 Provider checkpoint 时会
以 `recursive_agent_call` 阻断；不得自动重试形成递归。

小助手反向分派 checkpoint 时，Provider 可能是 本平台、DSH 或小助手官方智能服务；这与当前 Agent 主动
调用小助手 CLI 是两个方向。以平台返回的 Provider、版本、授权和能力探测结果为准，不能因为用户安装了本
Skill 就声称 本平台 一定支持被小助手调用。外部 Agent 不可调用、未授权或离线时，说明当前原因和仍可用
的本地能力；只有平台明确报告官方智能可用时才能建议切换，不得把专业版权益限制描述成技术故障。

Windows 与 macOS 都可在“设置 → Agent 接入”中启用自动分派、选择 Provider、设置超时并测试连接。启用后，
后台 Bridge 会自动领取、分派和回填 Agent 步骤；不要指导普通用户手工运行 `agent-claim` / `agent-complete`。
测试连接成功只证明 Provider 可用，仍须运行一个只读 checkpoint 确认原流程能够恢复。若请求截图，首次验收
选择不含敏感信息的区域，并确认出现读取范围虚线框、VLM 摘要与实际画面一致，且没有点击或输入。DSH 应
优先使用已安装命令或现有 npx 缓存；首次联网临时安装不是稳定运行方式。

## DSH 模型选择

选择 DSH 后，小助手会合并 DSH 已安装官方适配器的非秘密模型目录与 `settings.yaml` 中的自定义模型。DSH
Web 中使用凭据库启用、但不会写入 `settings.yaml` 的官方模型也应出现在下拉框；不能只检查该文件就判断
模型不存在。macOS 只在用户点击“刷新模型”时读取，Windows 在用户打开 Agent 配置或点击“刷新模型”时
读取；空闲 Bridge 不应周期探测 DSH，也不应反复弹出命令行窗口。

LLM 可跟随 DSH 默认模型或为小助手任务单独指定；VLM 只显示明确声明支持 `image` 输入的模型。小助手只
保存 Provider ID 与 Model ID，API Key 仍归 DSH 凭据库管理。没有可选 VLM 时，请用户先在 DSH Web 的
Models 页面配置真实支持图片输入的模型并刷新，不能把文字模型手工标成 `image` 绕过检查。“检查 VLM”
只检查声明与选择，不截图、不产生模型调用；真实视觉验收需另行说明截图将发送到哪个 Provider 并取得确认。

执行真实视觉读取时，DSH 屏幕插件先用 DSH 模型信息确认所选路由声明支持 `image`，通过后才截图。预检失败
是模型能力不匹配，不得先截取或上传屏幕内容。

## 验收边界

“设置 → Agent 接入”底部的“测试 Agent 屏幕理解…”只验证反向调用：先显示截图将发送到的 Provider/Model，
再由用户框选授权区域，最后展示理解摘要。不得把这个单画面测试描述为创建工作流。

可靠流程仍需用户与 Agent 多轮对话、跨页面观察、试运行、修正和验收。内部草稿生成即使通过语法校验，也
不能将“语法有效”等同于业务步骤正确，更不能跳过用户审阅直接安装或执行。
