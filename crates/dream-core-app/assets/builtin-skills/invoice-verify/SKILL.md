# 发票查验 Skill

## 概述

本 Skill 提供 本平台 发票查验能力。用户在对话中输入发票信息或上传发票文件后，自动识别票种、提取查验字段、判断字段是否完整、调用 `invoice_verification` 工具、解析并返回结果。全程在对话中完成，无需用户跳转外部平台。

## 可用工具

### invoice_verification - 发票查验

> **工具来源**：`yzf-general-mcp-server` 连接器（云帐房）
> **完整工具名**：`mcp__yzf-general-mcp-server__invoice_verification`
> 以下正文统一使用短名 `invoice_verification` 指代此工具。

调用发票查验平台，验证发票是否存在、票面信息是否一致、发票状态是否正常。

> **参数包裹规则**：调用本工具时，所有查验参数必须包裹在外层对象 `invoiceVerificationRequest` 中传入，不能直接平铺传参。

**参数说明**（均位于 `invoiceVerificationRequest` 内）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `fplx` | string | 是 | 发票类型枚举值，见下方票种枚举表 |
| `fphm` | string | 是 | 发票号码，支持 8 位或 20 位 |
| `kprq` | string | 是 | 开票日期，格式 `yyyyMMdd`，例如 `20240520` |
| `fpdm` | string | 条件必填 | 发票代码。非全电发票建议必传；8 位发票号码时部分票种必填 |
| `fpje` | string | 条件必填 | 发票金额或价税合计，字符串传参，例如 `"100.00"` |
| `jym` | string | 条件必填 | 校验码，传发票校验码后 6 位 |
| `xfsbh` | string | 否 | 销方纳税人识别号 |

**返回结构**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | `0` 接口处理成功，`101` 接口处理失败 |
| `message` | string | 响应消息 |
| `result.status` | string | 查验状态码，见下方状态码表 |
| `result.fplx` | string | 返回票种编码 |
| `result.invoiceMaster` | object | 发票主信息，不同票种返回字段不同 |
| `result.invoiceDetailList` | array | 发票明细列表，无明细的票种可能为空 |
| `pointsStatus` | number | 积分状态。`-1` 当前云帐房能力平台积分不足，`-2` 积分锁定失败。仅当值为 `-1` 或 `-2` 时需要提示用户 |
| `pointsLockRemark` | string | 积分锁定备注说明。仅当 `pointsStatus` 为 `-1` 或 `-2` 时才有值，需将此内容提示给用户 |

**使用示例**：

数电票三要素查验（20 位号码）：
```
调用 invoice_verification，设置：
- invoiceVerificationRequest.fplx = "QDFP"
- invoiceVerificationRequest.fphm = "25162000000012345678"
- invoiceVerificationRequest.kprq = "20260801"
- invoiceVerificationRequest.fpje = "1060.00"
```

增值税普通发票查验（8 位号码）：
```
调用 invoice_verification，设置：
- invoiceVerificationRequest.fplx = "ZZS_PTFP"
- invoiceVerificationRequest.fpdm = "3100201130"
- invoiceVerificationRequest.fphm = "08270567"
- invoiceVerificationRequest.kprq = "20200515"
- invoiceVerificationRequest.jym = "498634"
```

红字数电票查验（负数金额）：
```
调用 invoice_verification，设置：
- invoiceVerificationRequest.fplx = "QDFP"
- invoiceVerificationRequest.fphm = "26462000000624857311"
- invoiceVerificationRequest.kprq = "20260817"
- invoiceVerificationRequest.fpje = "-30000.00"
```

## 工作流程

### 步骤 1：提取发票信息

从用户文本或附件识别结果中提取以下字段：

| 字段 | 工具参数 | 说明 |
| --- | --- | --- |
| 发票类型 | `fplx` | 根据票面信息判断枚举值 |
| 发票代码 | `fpdm` | 8 位号码时通常必传 |
| 发票号码 | `fphm` | 支持 8 位或 20 位 |
| 开票日期 | `kprq` | 统一为 yyyyMMdd |
| 价税合计/金额 | `fpje` | 字符串传参，保留两位小数 |
| 校验码后 6 位 | `jym` | 普票类必传 |
| 销方识别号 | `xfsbh` | 选传 |

提取规则：
1. 不确定的字段不要强行填写。
2. 金额只保留数字、负号和两位小数（去除 ¥、元、逗号等非数字字符）。红字发票票面金额为负数属正常表现，不应去除负号。
3. 日期统一转换为 yyyyMMdd 格式。
4. 同一字段出现多个值时，标记为不确定，追问用户。

### 步骤 2：判断票种并校验必填字段

根据发票类型确定 `fplx` 枚举值和额外必填字段。详细票种枚举与字段规则见上方票种枚举表，完整规则见 `references/field_rules.md`。

**核心规则：**
- 发票号码为 20 位时，通常为数电票，优先使用三要素（发票号码 + 开票日期 + 价税合计）查验，`fplx` 取 `QDFP`。
- 发票号码为 8 位时，需根据票种传入发票代码 `fpdm` 及对应额外必填字段。
- 增值税普通发票类（`ZZS_PTFP` / `ZZS_PTFP_DZ` / `ZZS_PTFP_JS` / `ZZS_PTFP_TXF`）额外必填 `jym`（校验码后 6 位）。
- 增值税专用发票类（`ZZS_ZYFP` / `HYYSY_ZZS_ZYFP` / `JDCXS_TYFP` / `ZZS_ZYFP_DZ` / `ESCXS_TYFP`）额外必填 `fpje`。
- 全电发票类（`QD_PTFP` / `QD_ZYFP` / `QD_PAPER_ZYFP` / `QD_PAPER_PTFP`）建议传 `fpje`。

### 步骤 3：补充缺失字段

字段不完整时，只追问当前查验必须的缺失字段：
- 缺一个字段 → 只追问这一个。
- 缺多个字段 → 优先追问必填字段，一次性列出所有缺失项。
- 无法判断票种 → 提示用户上传发票文件或补充发票类型。

追问示例：
> "还需要开票日期和价税合计才能查验。请直接回复：开票日期 xxxx-xx-xx，价税合计 xx 元。"

### 步骤 4：调用 invoice_verification 工具

字段校验通过后，调用 `invoice_verification` 工具发起查验。

调用前，向用户确认：
> "我已收到发票号码、开票日期和价税合计，正在查验。"

调用示例：
```
invoice_verification(
  invoiceVerificationRequest = {
    fplx = "QDFP",
    fphm = "25162000000012345678",
    kprq = "20260801",
    fpje = "1060.00"
  }
)
```

### 步骤 5：解析并返回结果

根据工具返回的 `result.status` 处理结果。完整状态码表见 `references/field_rules.md`。

> **硬规则：不重试**。只要 `invoice_verification` 工具被调用并返回了结果（无论 `code` 是 `0` 还是 `101`，无论 `status` 是什么值，无论 `result` 是否为 null），即视为本次查验已完成，**不得再次发起 `invoice_verification` 调用**。调用结果可能是查验成功、查到但不一致、未查到、平台异常等，一律按下方对应分支处理。二次调用不仅浪费用户额度，还会触发税务局"同一张票每天 5 次"的限频（status = `002`）。

#### 5.1 查到且状态正常（status = 001，zfbz = 0）

展示工具返回的关键字段，格式：

```
查验平台查到了这张发票。

发票状态：正常
发票号码：xxx
开票日期：xxx
价税合计：xxx 元
销售方：xxx
购买方：xxx
查验时间：xxx

票面关键字段与本次输入一致。
```

#### 5.2 查到但状态异常（status = 001，zfbz != 0）

`invoiceMaster.zfbz` 值含义：`0` 正常，`2` 作废，`3` 红冲。

```
查验平台查到了这张发票，但发票状态为：已作废。

发票号码：xxx
开票日期：xxx
价税合计：xxx 元

这张票不建议继续用于报销、付款或入账，请联系开票方确认。
```

#### 5.3 查到但字段不一致（status = 006）

列出差异项：

```
查验平台查到了这张发票，但有字段不一致：

本次输入价税合计：1060.00 元
平台返回价税合计：1050.00 元

建议以查验平台返回结果为准，并核对你手上的发票文件是否被修改，或金额是否识别错误。
```

#### 5.4 平台未查到（status = 009）

**不能直接说"这是假票"。**

```
查验平台暂未查到这张发票。

本次查验信息：发票号码 xxx，开票日期 xxx，价税合计 xxx 元。

这不一定代表是假票。建议先核对发票号码、开票日期和金额是否录错；如果是当天刚开的票，可能存在平台数据同步延迟，可以稍后再查。
```

#### 5.5 查验平台异常（status = 004/005/105/106/108/998/999）

```
当前查验平台没有返回有效结果，可能是平台繁忙、网络超时或触发人工校验。
你可以稍后再试，或转人工协助查验。
```

#### 5.6 输入错误类（status = 1001-1010）

根据具体错误码提示用户修正对应字段：
- `1001` → 发票金额输入不正确
- `1002` → 发票校验码输入不正确
- `1004` → 发票代码不正确
- `1005` → 发票号码不正确
- `1006` → 超过五年的发票不能查验
- `1007` → 开票日期超过当前日期
- `1009` → 开票日期不正确
- `1010` → 价税合计不正确

#### 5.7 积分异常（pointsStatus = -1 或 -2）

无论 `result.status` 返回什么，只要 `pointsStatus` 有值且为 `-1` 或 `-2`，都必须向用户提示积分异常信息，并将 `pointsLockRemark` 的内容原样展示给用户。

| `pointsStatus` | 含义 | 处理方式 |
| --- | --- | --- |
| `-1` | 当前云帐房能力平台积分不足 | 展示 `pointsLockRemark` 内容，提示用户充值或联系管理员 |
| `-2` | 积分锁定失败 | 展示 `pointsLockRemark` 内容，提示用户稍后重试或联系管理员 |

提示话术示例：
```
当前查验服务积分不足，无法完成查验。

具体原因：{pointsLockRemark 的值}

请联系管理员处理或充值后重试。
```

```
积分锁定失败，暂时无法查验。

具体原因：{pointsLockRemark 的值}

请稍后重试，如问题持续请联系管理员。
```

## 结果展示顺序

1. **先说结论**：查到 / 未查到 / 查到但异常 / 暂时无法查验
2. **发票状态**：正常 / 作废 / 红冲 / 异常
3. **关键票面信息**：发票号码、发票代码、开票日期、价税合计、金额、税额、销售方、购买方、查验时间
4. **差异项**（有则展示）：用户输入值 vs 平台返回值
5. **下一步建议**：核对 / 稍后重试 / 联系开票方 / 转人工

## 展示字段优先级

| 字段 | 说明 | 来源 |
| --- | --- | --- |
| 查验结论 | 查到、未查到、异常、暂时无法查验 | 根据 `result.status` 判断 |
| 发票状态 | 正常、作废、红冲、异常 | `invoiceMaster.zfbz` |
| 发票类型 | 平台返回的票种 | `result.fplx` |
| 发票号码 | 平台返回或用户输入 | `invoiceMaster.fphm` |
| 发票代码 | 有则展示 | `invoiceMaster.fpdm` |
| 开票日期 | 平台返回 | `invoiceMaster.kprq` |
| 价税合计 | 平台返回 | `invoiceMaster.jshj` |
| 金额 | 有则展示 | `invoiceMaster.je` |
| 税额 | 有则展示 | `invoiceMaster.se` |
| 销售方 | 平台返回 | `invoiceMaster.xfmc` |
| 购买方 | 平台返回 | `invoiceMaster.gfmc` |
| 查验时间 | 本次查验时间 | 当前时间 |
| 差异项 | 与用户输入不一致的字段 | 对比输入与返回 |
| 下一步建议 | 核对、稍后重试、联系开票方、转人工 | 根据 `result.status` 判断 |

## 异常处理

| 异常情况 | 处理方式 |
| --- | --- |
| 缺少发票号码 | 提示用户补充发票号码，或上传发票文件 |
| 缺少开票日期 | 提示用户补充开票日期 |
| 缺少金额 | 根据票种提示补充价税合计、不含税金额或校验码 |
| 附件无法识别 | 提示用户上传更清晰的文件，或手工输入关键字段 |
| 票种无法判断 | 让用户补充发票类型，或上传完整发票文件 |
| 查验平台未查到 | 提示未查到和可能原因，不判定假票 |
| 查验平台超时 | 提示稍后重试 |
| 查验平台要求验证码 | 提示需要人工协助或转人工 |
| 平台返回状态异常 | 明确展示状态，并提示联系开票方确认 |
| `pointsStatus` = -1（积分不足） | 展示 `pointsLockRemark` 内容，提示用户充值或联系管理员 |
| `pointsStatus` = -2（积分锁定失败） | 展示 `pointsLockRemark` 内容，提示用户稍后重试或联系管理员 |
| 工具已返回结果（无论 `code`/`status` 取值） | **不重试**，按 `status` 对应分支处理结果 |

## 附件识别

当用户上传 PDF、OFD、图片或截图时：
1. 识别附件中的发票类型、发票号码、开票日期、金额等字段。
2. 判断查验字段是否完整。
3. 字段完整时直接查验。
4. 字段不完整或识别不清时，追问用户补充。

识别清楚时回复示例：
> "我识别到这是一张电子发票，发票号码 25162000000012345678，开票日期 2026-08-01，价税合计 1060.00 元。正在查验。"

识别不清时回复示例：
> "我识别到发票号码 25162000000012345678，但价税合计看不清。请补充票面价税合计金额。"

## 安全和边界

- 系统只返回查验平台结果，不做最终法律认定。
- "未查到"不等于"假票"，话术必须表达清楚。
- 群聊中展示税号、身份证号、联系方式等敏感信息时，应按企业安全策略脱敏。
- 用户上传的发票文件是否保存，需要遵守企业留档规则；没有明确规则时，不默认长期保存。
- 查验结果是否写入报销、付款、档案或开票任务，需要业务侧确认后再做。

## 查验频率限制

国家税务总局规定，同一张发票每天最多查验 5 次。超过限制后查验平台会拒绝请求（对应状态码 `002`）。

注意事项：
- 同一用户反复查验同一张发票时，主动提醒此限制，建议确认信息后再提交。
- 如果用户只是修改了某个字段（如金额输错），提示这是当天剩余的查验次数，请仔细核对后再查。
- 收到 `002` 状态码时，提示用户当天查验次数已用完，明天再试。

提示话术示例：
> "提醒一下，同一张发票每天最多可查验 5 次，请确认信息无误后再提交查验。"

> "这张发票今天的查验次数已用完（税务局限制每天 5 次），请明天再试。"
