# Expense Merger — 报销发票合并 + 城市分类汇总

输入一个目录，输出一份带封面汇总表 + 全部发票正文的合并 PDF。**OFD 和 PDF 混合自动处理**，按城市分类统计金额。

适用：差旅报销前的发票整理，特别是一次出差混合了高铁/机票/酒店多种发票时。

---

## 工作流（按顺序执行，不要跳步）

### Step 1：识别输入模式

接到目录路径后，先判断它是哪种：

| 模式 | 判定 | 处理 |
|---|---|---|
| **单批次** | 目录里直接有 `.ofd` 或 `.pdf` 文件 | 处理这一个目录 |
| **父目录** | 目录里只有子目录，没有发票文件 | 遍历每个子目录，按“单批次”逐个处理 |

判断逻辑：
```bash
# 当前目录有发票文件 → 单批次
find "<dir>" -maxdepth 1 -type f \( -iname "*.ofd" -o -iname "*.pdf" \) | head -1
```

如果是父目录，对每个子目录执行 Step 2-5。**已存在 `<子目录名>_报销汇总.pdf` 的跳过**，并在最终报告中标出“已处理”。

### Step 2：确保 Python 环境就绪

skill 用本地 venv 跑 `easyofd + pypdf + reportlab`。第一次跑时自动 bootstrap。

下文的 `<SKILL_DIR>` 指本技能所在目录，`<目标目录>` 指存放发票的文件夹：

```bash
bash <SKILL_DIR>/scripts/setup.sh
```

setup.sh 是幂等的——已存在就直接退出。venv 路径固定 `~/.cache/expense-merger-venv/`。

### Step 2.5：首次使用必须先设常驻城市（只做一次）

检查 `scripts/config.py` 里的 `HOME_CITIES`：

```bash
grep -n "^HOME_CITIES" <SKILL_DIR>/scripts/config.py
```

- **已填**（非空列表）→ 直接进 Step 3，**不要再问用户**
- **是空列表 `[]`** → 问用户一句：“你常驻哪个城市？出差城市判定要用它。”拿到答复后写进 `config.py`，例如 `HOME_CITIES = ["北京"]`

**这一步不能跳。**常驻城市为空时，脚本分不出行程哪一头是家，会把**起点**当成目的地，而且不报错。`extract.py` 因此内置了拦截：未配置就退出并提示，不会带着错值往下跑。

顺带可问一句是否有常走的经停站（写进 `TRANSIT_HINTS`），没有就留空，不影响正确性。

### Step 3：提取每张发票的关键信息

对目标目录跑 `extract.py`：

```bash
source ~/.cache/expense-merger-venv/bin/activate
python3 <SKILL_DIR>/scripts/extract.py "<目标目录>"
```

输出 `<目标目录>/.manifest.json`，每张发票一条记录，字段：

| 字段 | 含义 |
|---|---|
| `file` / `ext` | 文件名 / ofd 或 pdf |
| `amount` | 金额（取价税合计，否则取最大金额） |
| `type` | **业务类型**：高铁/机票/酒店/出租网约车/通行费/停车费/餐饮/会议/办公用品/通讯/礼品/其他 |
| `invoice_kind` | **票面形式**：增值税专用发票/增值税电子普通发票/全电发票/铁路电子客票/航空运输电子客票行程单/通行费电子发票/定额发票/其他票据 |
| `category_guess` | **费用科目**：差旅费-交通/差旅费-住宿/差旅费-市内交通/办公费/通讯费/会议费/待定 |
| `needs_decision` | 科目归属票面判不出来，需要人来定 |
| `has_alcohol` / `has_tobacco` | 票面明细里有没有酒水/烟草 |
| `flags` | 风险标记：专票用于招待 / 单独酒类发票 / 含烟草 / 缺日期 / 缺金额 |
| `date` | 开票日期或行程日期 |
| `route_or_seller` | 高铁“出发站→到达站”；机票“X→Y”；酒店销售方公司名 |
| `city_guess` | 脚本初判城市 |
| `text_preview` | 前 300 字原文（供复核用） |

**业务类型与票面形式是两个维度，别混。** 同一顿饭可以开成专票也可以开成普票，业务类型都是“餐饮”，但票面形式决定能不能抵扣。

### Step 4：复核并确定城市分类

**这是第一个必须人来判的点**。脚本的 `city_guess` 是基于关键字的，对以下情况会判错：

| 难点 | 处理原则 |
|---|---|
| **高铁经停站** | 行程目的地 = 路线中**非常驻地（`config.HOME_CITIES`）且非过路站（`config.TRANSIT_HINTS`）**的那一站。例：设常驻地为北京，则“北京南→济南西→青岛北”的城市是“青岛” |
| **酒店所在地** | 用统一社会信用代码的**第 3-8 位行政区划码**定位（先查地级市，查不到回退省会），再用公司名里的省份关键字兜底。例：91**3701**00… → 济南 |
| **机票** | 备注栏会写“订单号:xxx,YYYY/M/D 城市-城市”，非常驻地那个就是目的地 |
| **市内交通/餐饮** | 通常按出差主城市归属（看日期判断属于哪次出差） |
| **同一批次混了多趟出差** | 按时间聚类拆开（例：3/10-11 一趟、3/18-20 一趟、3/25-27 一趟） |

读完 `.manifest.json` 后，**为每条记录写入确定的 `city` 和精简的 `desc`**（一句话说明，例：“G101 北京南→济南西”、“某某酒店 2 晚”），保存为 `.manifest_final.json`。

### Step 4.5：确定费用科目（凡 `needs_decision` 为真的都要问）

**这是第二个必须人来判的点，而且比城市更容易出错。**

脚本能认出票面写的是什么，认不出这笔钱该记哪个科目——因为决定科目的信息不在票面上。

**最典型的是餐饮：**

| 同一张餐饮发票 | 记什么科目 | 判据 |
|---|---|---|
| 出差期间自己吃饭 | 差旅费 | 只有本人/同事，无外部人员 |
| 请客户吃饭 | **业务招待费** | 有外部单位人员参与 |

票面上只有金额、日期、商家名，**没有“谁在场”这个信息**。所以脚本一律标 `category_guess: 待定` + `needs_decision: true`，由你问用户，不许替用户猜。

问法（一次问完，别挤牙膏）：

> 这批里有 N 张餐饮/礼品票需要定科目：
> 1. 3/19 某餐饮商户 ¥2,860（票面含酒水）
> 2. 3/20 某商行 ¥980（礼品）
>
> 分别是差旅期间自用，还是招待客户？招待的话请给：招待事由、被招待单位、参与人数。

**判定为业务招待费的，必须补齐三项**（写进该条记录的 `entertainment` 对象）：

```json
"entertainment": { "reason": "客户方案沟通晚宴", "party": "某集团信息中心", "headcount": 8 }
```

缺任何一项，封面的招待费明细表会显示【待补】并给出提示。多数企业财务制度要求这三项齐全，缺了会被打回。

**招待费的两条硬提示（工具只标记，不替用户算税）：**

- 交际应酬消费属个人消费，**进项税额不得抵扣**（财税〔2016〕36 号附件1 第二十七条）。所以招待场景取得增值税专用发票也抵扣不了——脚本会打 `专票用于招待` 标记，提示确认是否应改开普通发票。
- 业务招待费在企业所得税汇算清缴时按发生额 60% 扣除、且不超过当年销售（营业）收入 5‰，两者取低（《企业所得税法实施条例》第四十三条）。**这是企业年度层面的事，不在单次报销范围内**，工具只在封面附一句说明，不做计算。

**酒水与烟草**：

- 餐饮发票里含酒水是正常的，不额外处理
- **脱离餐饮场景的单独酒类零售发票**打 `单独酒类发票` 标记——多数企业制度需附额外说明或不予报销
- 烟草一律打 `含烟草` 标记——多数企业制度不予报销

这三类标记都只是**提示**，最终以用户所在企业的财务制度为准。skill 不替财务做决定。



**desc 规范**：
- 高铁：只写“车次 起点站→终点站”，**不写座位等级**（一等座/二等座/商务座/站票一概不显示）
- 机票：“承运商或代理 X→Y”
- 酒店：“酒店名 N 晚”（晚数从税额行的数量字段或单价×数量推算）

### Step 5：生成封面 + 合并 PDF

跑 `build.py`，传入目标目录：

```bash
python3 <SKILL_DIR>/scripts/build.py "<目标目录>"
```

它会读 `.manifest_final.json`，把所有 OFD 转 PDF，加封面后合并为 `<目录名>_报销汇总.pdf`，写回目标目录。

封面结构（**招待费那节只在真有招待费时才出现**，所以章节号是动态的）：

| 节 | 内容 |
|---|---|
| 一、城市汇总 | 城市 / 笔数 / 小计 / 占比 ＋ 合计行 |
| 二、费用科目汇总 | 科目 / 笔数 / 小计 / 占比 ＋ 合计行。**城市回答“钱花在哪”，科目回答“记到哪个账上”，财务要的是后者** |
| 三、业务招待费明细 | 日期 / 招待事由 / 被招待单位 / 人数 / 金额。缺项显示【待补】，附税前扣除口径说明。**无招待费时整节不出现** |
| 四、发票明细 | # / 城市 / 科目 / 类型 / 日期 / 说明 / 金额。风险标记挂在说明列括号里 |
| 五、说明 | 张数与格式、城市分类口径、每趟出差概述、合计金额，末尾附“需人工确认的项”清单 |

### 配置在哪改

个人化的东西全在 `scripts/config.py`，改这一个文件就能适配别人的情况：

| 配置 | 作用 |
|---|---|
| `HOME_CITIES` | **必填**。常驻城市，用于从行程里剔除本地站。**留空脚本会停下来要求先填**——空值会让目的地判定静默取到起点 |
| `TRANSIT_HINTS` | 选填。常见过路站，不作为目的地判断依据 |
| `CATEGORY_BY_TYPE` | 业务类型 → 会计科目的映射 |
| `AMBIGUOUS_TYPES` | 归属判不出来、必须问人的类型（默认餐饮/礼品/其他） |
| `ALCOHOL_KEYWORDS` / `TOBACCO_KEYWORDS` | 酒水、烟草识别词 |
| `RISK_NOTES` | 各风险标记对应的提示文案 |

`scripts/extract.py` 里的 `CITY_CODE` 表只列了直辖市、省会、计划单列市和常见出差城市，不在表里的自动回退到省会。要加城市直接往表里补，格式是行政区划码前 4 位（查国标 GB/T 2260）。

## 关键技术注意事项

### OFD 处理

OFD 是国标电子发票，本质是 ZIP+XML。用 `easyofd` 转 PDF。**两个坑必须处理**（脚本里已经包了）：

1. **中文字体注册必须早于 easyofd 调用**：`reportlab` 默认不认“宋体”，要先 `pdfmetrics.registerFont(TTFont("宋体", "/System/Library/Fonts/Supplemental/Songti.ttc"))` 把别名注册好，否则高铁票的批注层会渲染失败。

2. **空签名块的 assert bug**：高铁电子客票的签名块经常是空的，`easyofd.parser_ofd.OFDParser.get_xml_obj` 会在 `assert label` 处崩。需要 monkey-patch：

```python
import easyofd.parser_ofd.ofd_parser as _op
_orig = _op.OFDParser.get_xml_obj
def _safe(self, label):
    if not label: return {}
    return _orig(self, label)
_op.OFDParser.get_xml_obj = _safe
```

`build.py` 已经内置了这两段。

### 城市识别难点（脚本不能完全自动）

- 高铁 OFD 的 `<TextCode>` 节点出现顺序不固定，出发站和到达站可能颠倒。脚本只列出两站，由 AI 判断方向。
- 酒店发票的 PDF `pdftotext -layout` 输出，销售方名称在“销 售 方”下一行。注意中文夹空格。
- 机票备注里的日期格式是 `2026/3/18`（不是 `2026-03-18`），分号分隔订单号和路线。

### 已处理目录的判断

凡是目录里已经有 `<目录名>_报销汇总.pdf` 的文件，认为已处理。要重处理就先删除这个文件。**不要根据 `.manifest_final.json` 是否存在判断**——因为它可能是上一次中断时留下的。

## 输出风格

报告给用户的总结**只写关键信息**：
- 文件路径
- 城市汇总表（markdown）
- 总金额
- 异常情况（识别不出的发票、需要人工核对的）

**不要写**：技术过程细节（多少张转换成功、字体警告等）、emoji 装饰、`总而言之` 类废话。

## 字段命名约定

manifest JSON 用这些字段名，不要自创：

```json
{
  "file": "26449...pdf",
  "ext": "pdf",
  "amount": 703.50,
  "type": "高铁",
  "date": "2026-03-18",
  "route_or_seller": "北京南→济南西",
  "city_guess": "济南",
  "text_preview": "..."
}
```

最终 manifest 额外加 `city` 和 `desc`：
```json
{ ...(上面字段)..., "city": "济南", "desc": "G101 北京南→济南西" }
```

`build.py` 只认 `city` / `type` / `date` / `desc` / `amount` / `file` 这 6 个字段，其他忽略。
