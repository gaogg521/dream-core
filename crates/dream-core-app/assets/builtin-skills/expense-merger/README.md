# expense-merger

把一个文件夹里混着的 **OFD + PDF 报销发票**合并成一份带封面的 PDF：自动识别票种与费用科目，按城市和会计科目两个口径出汇总表，业务招待费单独成节。

国内电子发票有两种格式：税务系统给的是 **OFD**（国标，本质是 ZIP+XML），商家开的多半是 PDF。一次出差下来两种混在一起，交给财务前要手工合并、手工统计——这个工具就干这件事。

这是一个遵循 SKILL.md 规范的 Agent Skill，可装在支持该规范的 AI 工作台里使用。核心解析逻辑是纯 Python，脱离任何 AI 环境也能单独跑。

---

## 它解决什么

| 手工做 | 这个工具 |
|---|---|
| OFD 打不开、要一张张转 PDF | 自动转，含高铁票签名块崩溃的兼容处理 |
| 金额一张张抄进 Excel | 自动提取价税合计 |
| 按城市分摊靠记忆 | 从行程和统一社会信用代码里推 |
| 差旅费和招待费混在一起报 | 两个口径分开出表，招待费单独成节 |
| 招待费忘了写事由和人数被打回 | 缺项显示【待补】并提示 |

## 设计上的一条原则

**能从票面读出来的，脚本做；读不出来的，问人，不猜。**

最典型的是餐饮票：

| 同一张餐饮发票 | 科目 | 判据 |
|---|---|---|
| 出差期间自己吃饭 | 差旅费 | 只有本人和同事 |
| 请客户吃饭 | 业务招待费 | 有外部单位人员 |

票面上只有金额、日期、商家名，**没有“谁在场”这个信息**。所以这类票一律标成 `needs_decision`，由使用者决定，脚本不替你猜——猜错的代价是财务打回或税务风险，比多问一句贵得多。

## 招待费怎么处理

判定为业务招待费的，要求补三项：**招待事由、被招待单位、参与人数**。这不是税法规定的字段，是多数企业财务制度的通行要求——报销单上写不出“谁、为什么、几个人”，基本会被打回。缺项在封面上显示【待补】。

工具还会打两类提示标记：

- `专票用于招待` —— 交际应酬消费属个人消费，进项税额不得抵扣（财税〔2016〕36 号附件1 第二十七条）。招待场景拿到专用发票也抵扣不了，提示确认是否应改开普通发票。
- `单独酒类发票` / `含烟草` —— 餐饮票里含酒水是正常的，但脱离餐饮场景的单独酒类零售发票、以及烟草类支出，多数企业制度需附额外说明或不予报销。

**工具只做标记，不替你算税。** 业务招待费按发生额 60% 扣除、且不超过当年销售（营业）收入 5‰ 取低（《企业所得税法实施条例》第四十三条），那是企业年度汇算清缴层面的事，不在单次报销范围内，也会随规定变化。封面只附一句口径说明，具体以所在企业财务制度和当年最新规定为准。

## 用法

```bash
# 首次运行会自动建 venv（easyofd + pypdf + reportlab）
bash scripts/setup.sh

# 1. 扫描目录，提取每张票的信息
python3 scripts/extract.py <发票目录>     # 生成 .manifest.json

# 2. 复核城市与费用科目，补上 city / desc / category，另存为 .manifest_final.json
#    （作为 Agent Skill 使用时，这一步由 AI 读 .manifest.json 后完成并向你提问）

# 3. 生成封面 + 合并
python3 scripts/build.py <发票目录>       # 输出 <目录名>_报销汇总.pdf
```

输入可以是单个出差文件夹，也可以是装着多个出差文件夹的父目录（已生成过汇总的自动跳过）。

## 封面结构

```
一、城市汇总          钱花在哪
二、费用科目汇总      记到哪个账上（财务要的是这个）
三、业务招待费明细    仅当有招待费时出现，缺项标【待补】
四、发票明细          风险标记挂在说明列
五、说明              含“需人工确认的项”清单
```

## 配置

个人化的东西全在 `scripts/config.py`：

| 配置项 | 作用 |
|---|---|
| `HOME_CITIES` | **必填**。常驻城市，用于从行程里剔除本地站（设常驻北京，则“北京南→济南西”的目的地是济南）。**留空脚本会停下来要求先填** |
| `TRANSIT_HINTS` | 常见过路站，不作为目的地 |
| `CATEGORY_BY_TYPE` | 票据类型 → 会计科目映射 |
| `AMBIGUOUS_TYPES` | 归属必须问人的类型，默认餐饮/礼品/其他 |
| `ALCOHOL_KEYWORDS` / `TOBACCO_KEYWORDS` | 酒水、烟草识别词 |
| `RISK_NOTES` | 风险标记对应的提示文案 |

`scripts/extract.py` 里的 `CITY_CODE` 表只列了直辖市、省会、计划单列市和常见出差城市，不在表里的自动回退到省会。要加城市按国标 GB/T 2260 往表里补行政区划码前 4 位即可。

## 技术说明

**OFD 解析的两个坑**（脚本里都处理了）：

1. 中文字体注册必须早于 `easyofd` 调用，否则高铁票的批注层渲染失败
2. 高铁电子客票的签名块经常是空的，`easyofd` 会在 `assert label` 处崩溃，需要 monkey-patch

**统一社会信用代码取城市**：18 位代码的第 3-8 位是登记管理机关行政区划码（前 2 位省、3-4 位市、5-6 位区县）。先按地级市码查，查不到回退省会。

> 早期版本这里错过一次：把省级码当成了市级码，`9132` 写成石家庄（实际 32 是江苏）、`9134` 写成唐山（实际 34 是安徽）；字典里还有重复键，后写的静默覆盖先写的，秦皇岛和邯郸那两条从来没生效过。查表类的东西错了不会报错，只会安静地给出错误答案——这类 bug 值得单独写测试。
