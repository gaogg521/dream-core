# 判断规则与输出模板

## 一、数据源优先级

**天气（按优先级检索，首个拿到结构化结果的即止）：**
1. 出发地/目的地市气象局官网（如 weather.sz.gov.cn、bj.cma.gov.cn）——最准，含逐时预报与生活指数
2. 中国气象局 weather.cma.cn
3. 主流媒体转发的气象台原文（核对发布单位与发布时间，超过 24 小时的预报需重搜）

检索词模板：`{城市} {月}月{日}日 天气预报 {年}`、`{城市}气象台 {月}月{日}日 预报`。

**航班历史数据：**
1. 飞常准（variflight）：准点率、平均延误、取消率、机型、机龄、值机柜台
2. FlightAware：实际起降时刻、历史登机口（"left Gate XXX"）、滑行时间
3. Trip/携程航班状态页：备用口径（注意其"30 分钟内算准点"口径偏宽松）

检索词模板：`{航班号} 航班 {出发城市} {到达城市} 起飞时间 准点率`、`{航班号} flightaware`。

## 二、延误概率合成模型

**基准值**：该航班历史准点率（飞常准口径优先）。无航班号时用该航线当日同航司均值的定性表述。

**加权因子（逐项检查，命中则上调风险）：**

| 因子 | 判断依据 | 影响 |
|---|---|---|
| 起飞端午后对流 | 起飞时段落在 12:00-17:00 且预报有雷阵雨/局地阵雨 | 中幅上调 |
| 到达端天气过程覆盖 | 目的地降水过程时段与计划落地时段重叠 | 中幅上调 |
| 前 1-3 日同班实际表现 | FlightAware 近日记录出现 >30 分钟延误 | 小幅上调 |
| 流量高峰 | 早高峰（7:00-9:30）、晚高峰（17:00-20:00）起降于千万级机场 | 小幅上调 |
| 老机型 | 机龄 >20 年 | 轻微上调（排故概率） |
| 顺风因素 | 两端均晴好、非高峰、宽体机 | 下调 |

**输出三档概率**（区间表述，不给伪精确个位数）：
- 延误 15~45 分钟概率
- 延误超 1 小时概率
- 取消概率（直接引用历史取消率区间）

**缓冲建议规则**：按"计划落地 + 合成延误中位数 + 30 分钟地面"给出落地后行程的最早安全时间点。

## 三、穿衣温度带规则

| 时段温度 | 建议 |
|---|---|
| >28℃ | 盛夏装：短袖、薄长裤/裙，防晒 |
| 22~28℃ | 短袖 + 薄长裤 |
| 15~22℃ | 长袖 + 薄外套 |
| <15℃ | 外套 + 长裤，注意风 |
| 预报有降水 | 追加雨具（兼顾遮阳则注明） |

**温差衔接规则（硬性）**：两地同时段温差 ≥8℃ 时，必须给"出发穿着 + 随身携带到达装"的衔接方案，而非让用户按单一端穿着。

## 四、地面通行概率与换航司规则

**概率估算**：按 `airline-airport-kb.md` 的机场结构与航司归属估算三态概率（靠桥 / 卫星厅含捷运 / 远机位摆渡车），分出发端、到达端给出。估算方法：历史登机口记录 > 机场结构归属 > 航司主场权重，置信度分高/中/低标注。

**换航司触发阈值**：两端合计（卫星厅 + 摆渡车）概率 **>30%** 时触发替代航司建议。

**建议话术规则**：
- 触发时：给出同航线替代航司，并附逐端对比（哪个航司在哪端占优），不只说"换"
- 未触发时：明说"不建议换"及理由（主场优势、卫星厅用户归属等结构性原因）
- 注意反直觉情形：基地航司在本地反而更可能进卫星厅（例：深航之于深圳卫星厅），建议前必须逐端核实

**常飞航司判断**：同会话内统计航班号二字码前缀频次，结合该航司在此航线的班次密度，判断用户常旅客身份并说明依据。

## 五、报告模板

```
试跑/出行报告：{月}月{日}日 {出发} → {到达}（{航班号或"未提供航班"}）

1）天气
出发端 · {城市}（{出门-起飞时段}）：{天气、温度、风、关键提示}
到达端 · {城市}（{落地时段}）：{天气、温度、风、关键提示}
两地温差 {X}℃，{是否需管理}

2）延误概率
{分档概率 + 因子表 + 缓冲建议}

3）穿衣建议
出发：{...}；到达：{...}；衔接：{...}

4）地面通行（有航班号时）
出发端：靠桥 X% / 卫星厅 X% / 摆渡车 X%（置信度 X）
到达端：靠桥 X% / 卫星厅 X% / 摆渡车 X%（置信度 X）

5）航司判断
{前缀 → 航司 → 常旅客判断}；{换/不换 + 逐端对比理由}
```

**格式硬性要求**：零 emoji；数字加粗或入表；概率必标来源与估算属性；落地行程缓冲时间单独成句。
