# 自主发明增强方法

从一句话、零散构思或不完整材料生成交底书时读取。目的不是机械增加模块，而是自主构造一个具有技术问题、技术手段、作用机制和可测效果的完整方案。

## 1. 把原始输入变成发明种子

先提取四项；缺失项直接合理补充，不向用户提问：

- **技术对象**：要处理的设备、数据、材料、信号、过程或环境；
- **目标变化**：希望减少、提高、稳定、识别、控制或转换什么；
- **现有限制**：精度、速度、资源、可靠性、波动、隐私、能耗或制造条件；
- **可执行结果**：最终由哪个实体产生何种物理、数据或控制输出。

若一句话存在多个解释，在内部列出候选解释，选择最能形成可测技术闭环的一种作为主解释，其他解释放入替代方案。

## 2. 技术性转换

原始输入偏审美、心理、偏好、商业规则或信息展示时，使用下列问题把它转换成技术方案：

1. 哪种可采集数据或物理量代表该输入？
2. 如何提取、编码、校准或融合这些数据？
3. 数据如何改变设备、材料、信号或计算过程？
4. 需要满足哪些物理、资源、时间、安全或精度约束？
5. 如何检测输出偏差并反馈修正？
6. 哪个指标可以验证方案确实产生技术效果？

不要把用户偏好本身称为技术效果。可复现性、控制误差、处理延迟、资源占用、信号质量、稳定性、可靠性、材料性能和制造一致性等才是优先考虑的技术指标。

## 3. 生成候选技术路线

内部生成至少三条真正不同的路线。根据对象选择相关机制，不必每类都使用：

- **检测—决策—执行—反馈路线**：通过传感、状态估计、控制输出和误差校正形成闭环；
- **多源特征耦合路线**：让两个以上输入在功能上相互影响，而不是简单加权或并列展示；
- **约束求解路线**：在总量、边界、资源、库存、能耗或安全约束下求解可执行输出；
- **时序自适应路线**：利用历史状态、变化率、滞回、平滑或在线校准减少波动；
- **结构协同路线**：通过部件形状、相对位置、连接、传动、流道或装配关系产生效果；
- **材料—工艺耦合路线**：通过组分作用、比例区间、加入顺序、温度/压力/时间条件形成性能差异；
- **容错与降级路线**：在输入缺失、部件故障或资源不足时保持可控输出；
- **可观测与可取证路线**：把关键技术特征体现在设备结构、接口行为、输出数据或可测性能中。

候选路线之间必须在核心机制上有差别，不能只是更换名称或应用场景。

## 4. 选择主路线

用以下维度比较候选路线，选择综合最强者作为交底书主方案：

| 维度 | 判断重点 |
|---|---|
| 技术性 | 是否具体改变物理、数据、信号、材料或设备过程 |
| 差异化潜力 | 是否形成不易由单一常规技术直接得到的特征组合 |
| 功能性相互作用 | 多个区别特征是否共同作用并产生统一效果 |
| 可实施性 | 能否给出组件、步骤、条件和端到端实施例 |
| 保护范围 | 是否支持上位概念、优选特征和替代实现 |
| 可检测性 | 竞争方案采用时能否通过产品、接口或测试识别 |
| 抗规避性 | 删除或替换单个次要特征后核心关系是否仍可覆盖 |

若最有创造性的路线暂时缺少实验，仍可作为主路线，但必须提供具体验证方法并标为 `V`，不能声称已验证。

## 5. 构造强发明核心

优先形成包含 2—4 个相互作用特征的组合。例如：

> 特征 A 获取或生成目标状态；特征 B 根据该状态改变处理路径；特征 C 检测执行偏差并回传修正 B；由此在约束 D 下改善指标 E。

以下组合通常偏弱，需要继续增强：

- 只把已知算法换到新行业；
- 只增加“根据用户偏好推荐”；
- 只把多个传感器数据相加；
- 只把人工步骤改成计算机执行；
- 只改变展示颜色、形状或界面布局；
- 只罗列 AI、云端、区块链而没有新的技术关系。

增强时优先改变特征之间的关系、控制时序、反馈方式、约束求解或结构配合，而非单纯增加组件数量。

## 6. 按领域补齐条件

### 软件与 AI

补齐数据来源、输入输出定义、预处理、关键模型/算法机制、训练或更新方式、与具体场景的结合、部署位置、资源约束、异常输入和可量化指标。

### 机械与电子

补齐部件、形状/构造、相对位置、连接、动作顺序、传感器、执行器、反馈、材料选择、装配和故障保护。

### 材料、配方与工艺

补齐组分及作用、比例关系、范围选择依据、混合/加入顺序、温度、压力、时间、粒径或环境条件、性能测量、对照组和替代组分。没有实验时可以设计实验矩阵，但不能编造最佳比例或测试结果。

## 7. 检索后的自动增强

将检索到的接近方案拆成特征集合，重点寻找：

- 未公开的控制闭环；
- 未建立的输入输出内在关联；
- 未同时考虑的约束；
- 未解决的异常或边界状态；
- 未产生的可测技术效果；
- 可由另一候选路线替代的常规核心。

如果区别只剩用途、名称或用户群体，应更换主路线。不得简单把多个现有技术特征堆叠后称为创造性；要说明组合后的功能性相互作用及其效果。

## 8. 输出来源边界

只在独立的专利分析文件中用简短清单说明：

- 用户给出了什么；
- 技能为了创造性补充了什么；
- 哪些补充需要实验或样机验证。

无需向用户确认这些补充，也不要在正文到处插入问号或占位符。分析文件记录候选路线、选择依据、U/S/V/R 来源、检索过程、支持矩阵和建议验证事项。

独立的技术交底书文件必须是完整净稿：行政信息可以写“未提供”，但不出现 U/S/V/R 标签、创造性补充声明、候选路线比较、检索过程或风险评分。分析文件和交底书应使用相同的发明名称、术语、参数关系、实施例编号与附图编号。
