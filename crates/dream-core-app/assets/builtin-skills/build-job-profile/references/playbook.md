# Playbook：从业务需求生成可评审的岗位画像

## 使用场景

用人经理提出了一个新岗位，但现有信息仍是零散的业务目标、任务和少量要求。HR 需要在编写 JD 或设计面试方案前，把这些信息整理为双方可评审的岗位画像。

## 推荐输入

```text
我们准备招聘一名中国区 SaaS 客户成功经理。
招聘原因：减少新客户上线延期并提升续约。
关键任务：推进客户上线、维护客户健康度、识别并推动解决续约风险。
基本要求：能用英语主持客户会议。
汇报对象：客户成功总监。
请生成一份可评审的岗位画像，区分已确认信息、假设和待确认项。
```

## 执行方式

1. 先检查岗位名称、招聘原因、关键任务和基本要求是否满足最小输入。
2. 将业务目标转成岗位使命和 3—6 项结果责任。
3. 为每项责任补充可观察的成功证据，并标出尚未确认的指标或时间范围。
4. 推导能力标准和评估证据，将任职要求分为必须、优先、可培养、移除或待确认。
5. 输出假设、冲突、风险、人工复核点和下一步动作。

## 预期结果

得到一份包含九个固定部分的岗位画像，可供 HR 与用人经理评审，并可继续交接给 JD 生成或结构化面试设计。最终岗位定级、薪酬、招聘要求和录用决定仍由企业授权人员确认。

## 注意事项

- 不输入候选人敏感信息，也不要求本 Skill 评价或排名候选人。
- 年龄、性别、婚育、健康、民族、宗教等特征不得作为岗位筛选条件或代理条件。
- 市场数据、法律结论和企业制度未提供时不应臆造；需要时由 HR、法务或相关负责人复核。
