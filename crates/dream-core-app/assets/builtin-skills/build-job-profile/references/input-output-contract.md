# 输入与输出契约

## 输入模板

```text
岗位名称/类型：
为什么现在招聘（业务目标）：
入职后最重要的 2—5 项任务或结果：
基本要求或运行约束（至少 1 项）：
汇报对象与关键协作方（可选）：
成功指标/时间要求（可选）：
团队、行业、地点、工作方式、语言（可选）：
现有 JD、访谈纪要或其他单份文档（可选）：
画像用于哪个环节（可选）：
```

## 输入状态与处理

| 状态 | 条件 | 处理 |
|---|---|---|
| 充分 | 四项最小输入齐全 | 直接执行，不追问不必要问题 |
| 可补救 | 仅缺一个非关键项 | 明确假设并交付草案 |
| 不完整 | 招聘原因和关键任务同时缺失 | 最多提 3 个问题；仍无答案只给澄清模板 |
| 冲突 | 重要事实互相矛盾 | 并列两种口径并指定决策人 |
| 高风险 | 歧视、违法、欺骗或侵犯隐私 | 拒绝危险部分，改为工作相关替代方案 |

## 稳定表格字段

### 结果责任与关键任务

`结果责任｜关键任务｜成功证据/指标｜时间范围｜信息状态`

### 能力标准

`能力｜可观察行为｜重要性（核心/重要/加分）｜评估证据｜来源（用户事实/合理假设）`

### 任职要求分层

`要求｜来源口径｜建议层级（必须/优先/可培养/移除/待确认）｜与工作关联｜验证方式｜风险或说明`

教育、专业、证书、年限、雇主和行业背景只有在与关键工作或法律资格直接相关时才能列为必须；关联未建立时使用“优先”“可培养”或“待确认”，并建议用作品或行为证据验证。

## 证据标签

- `[已确认]`：用户或文档直接提供；
- `[假设]`：为形成可用草案而推断；
- `[建议]`：需要人工批准的设计建议；
- `[待确认]`：重要不确定性或冲突。

## 交付大小与截断处理

- 默认一条消息包含 1—9 节；最多 6 项结果责任、8 项能力和 8 行任职要求。
- 不为填表臆造数字指标或时间范围；若必须分两条，标注“第 1/2 部分”和“第 2/2 部分”，第 2 部分必须包含第 7—9 节。
- 用户反馈截断时，接受可见结果并立即补发缺失节，不争辩渲染问题；发送前检查 1—9 节标题及第 9 节的具体动作。

## 合规措辞

使用：“当前材料未发现明显的歧视性要求；仍需结合岗位事实和适用地区规则由 HR/法务复核。” 不使用“绝对无合规风险”等确定性表述。
